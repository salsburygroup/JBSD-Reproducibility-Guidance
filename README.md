# DRAFT — JBSD reproducibility guidance

**Draft for review. This guidance has not yet been adopted as JBSD policy or final author instructions.**

These checklists help authors prepare reproducible manuscripts and deposits. They explain how to meet the policy; they do not add requirements.

Authors do not submit completed checklists. Use only the checklists relevant to the methods and claims in the manuscript.

## Labels

- **Required:** The policy requires the item when the stated method or circumstance applies.
- **Conditional:** Provide the item only when it is relevant to a method, analysis, result, or restriction.
- **Recommended:** The item can make a deposit easier to understand or reuse, but its absence alone is not grounds for rejection.

## Author workflow

1. Read the JBSD policy and select the relevant checklist or checklists.
2. Prepare the files and documentation that support the principal claims.
3. Deposit the package in a recognized archival repository with a persistent identifier. GitHub may host development, but it does not replace an archival release.
4. Add the repository and identifier to the manuscript's Data Availability Statement.
5. Use the templates below if they make the deposit easier to navigate.

## For editors and reviewers

Editors may link authors to one or more relevant checklists in a consolidated request. Reviewers should assess whether the methods and deposited evidence support the manuscript's claims. They are not expected to audit every file. An editor may request additional material when a missing item prevents evaluation of reproducibility, validity, or research integrity.
